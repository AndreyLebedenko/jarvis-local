# Human-run verification handoff: story v1.9.1 heard-phrase Journal search

Executable from its own text, per Testing protocol item 4 (`CLAUDE.md`/`AGENTS.md`
"Testing protocol"). Run by a human; the agent prepared it and stops.

What this verifies: a phrase spoken only in a mode-3 (Text + voice) spoken
commentary locates the owning turn through the Journal search, displayed as a
distinctly labeled heard-phrase (locator) match with the canonical on-screen
answer as the authoritative content - and that the derivative stays out of
Jarvis's model-facing memory surfaces.

## Launch command (every step; repository root; never two instances at once)

```
python -m jarvis --status-console
```

### Step 1. Reach mode 3 (Text + voice) and produce a derivative

1.1. Launch `python -m jarvis --status-console`. The live response mode can
     only be one of text/voice/text_voice: check the Status-tab Response mode
     buttons. If "Text + voice" is not highlighted, press **Ctrl+Alt+O**
     (source: `config.py:140`; cycle order text -> voice -> text_voice ->
     text) until it is - from any starting mode this is at most two presses
     (from `text`: two; from `voice`: one; from `text_voice`: none).
     Alternatively click the "Text + voice" Status-tab button directly.

1.2. Ask a question that produces visible structure AND leaves natural room
     for spoken phrasing that differs from the on-screen wording. For
     example, ask: "расскажи кратко, как обслуживать реле, с тремя шагами".
     Expect: the canonical answer streams to the screen, then (after it
     completes) Jarvis speaks a shorter derivative commentary.

1.3. While the answer is on screen, pick a phrase that Jarvis said ONLY in
     the spoken commentary and that is unlikely to appear verbatim in the
     on-screen text (spoken commentary naturally paraphrases; e.g. if it said
     "короче говоря, главное не забыть про пыль" - remember "не забыть про
     пыль"). Write the exact phrase down.

1.4. Open the Journal tab for the current session: the assistant turn shows
     its canonical on-screen text and a collapsed "spoken aloud" block with
     the derivative. Confirm the phrase you wrote exists in the "spoken
     aloud" expansion.

### Step 2. Locator search finds the turn by the heard phrase

2.1. In the Journal tab, type the remembered phrase (e.g. "про пыль") into
     the Journal search box (placeholder "Search exact words or prefixes" /
     "Точные слова или начала слов"), next to the "Search Jarvis answers" /
     "Поиск ответов Jarvis" controls. Date filters are optional; leave them
     clear.

2.2. Expect, below the ordinary canonical results (there may be none):

    - a group headed "Found by something you heard" /
      "Найдено по фразе, которую вы слышали";
    - inside it, a hit for the mode-3 assistant turn with the dashed border
      and the tag "heard-phrase match" / "совпадение по услышанной фразе";
    - under it, the line "Shown on screen: ..." / "Было показано на экране: "
      containing the canonical answer exactly as it was streamed on screen -
      that line is the authoritative content; the search snippet above it is
      the heard fragment (recognition only).

2.3. Click the locator hit: the Journal jumps to the owning turn and
     highlights it, showing the canonical text.

### Step 3. Separation guarantees (each must hold)

3.1. **Canonical-only search stays clean.** Search for a phrase that exists
     ONLY in the derivative (part of your step-1 phrase, e.g. "про пыль").
     It must appear ONLY inside the locator group, never as an ordinary
     canonical search hit above it.

3.2. **No automatic retrieval promotion.** Ask a new ordinary question
     containing the derivative-only phrase, phrased so it needs history
     (e.g. "ты недавно про это говорил - что именно?"). Expect: the normal
     answer does not claim prior spoken content as conversation memory. (An
     automated test covers this at the retrieval layer;
     `tests/test_history_corpus.py::test_derivative_phrase_never_enters_
     hybrid_retrieval_candidates`; this step is the UI-level sanity check.)

3.3. **Model-facing exposure is UI-only (recorded decision, task 4).**
     `search_history` - Jarvis's own native history-search tool - must NOT
     surface the derivative. Three checks, from behavioral to direct:

     - Behavioral: in the SAME session ask Jarvis to search its own history
       for the exact derivative phrase, e.g. "поищи в истории нашего
       разговора фразу: <exact derivative phrase>". Expect: either no
       results, or results that do not contain the derivative text "spoken
       aloud" anywhere; no result labeled as a locator/heard-phrase match.
     - DIRECT check, executable and self-sufficient: after doing 3.3's
       behavioral ask, open `logs/jarvis.log` in the repository root (the
       engine log; the directory is `[logging] directory`, default
       `"logs"` - `src/jarvis/core/config.py:589`; the file name is fixed
       `jarvis.log` - `src/jarvis/core/log_config.py:25`). Find the request where the
       model answered your history-search prompt and check that IF it called
       the tool, every logged
       `Calling tool 'search_history' via 'history'` line's payload
       (`{'query': ...}` arguments) maps to an outcome that contains no
       derivative text - and that no `search_history` call returned a result
       labeled locator/heard-phrase. Tool calls with their arguments are
       logged at INFO by the MCP interception boundary
       (`src/jarvis/tools/interception.py`, "Calling tool" lines into
       `logs/` via `jarvis.core.log_config`, file name `jarvis.log`).
       Anything found must be the canonical text of events, never the
       spoken-aloud block. If the model never called `search_history` for
       the prompt, this is inconclusive - rephrase with an explicit "use
       your search_history tool" instruction and retry once.
     - Architectural backing (already machine-verified, listed as the
       reason this check can stay behavioral):
       `SPOKEN_DERIVATIVE.eligibility == {LOCATOR_ONLY}`
       (`src/jarvis/journal/provenance.py`) keeps the derivative out of the
       model's tool surface by construction, and
       `tests/test_history_corpus.py::test_canonical_search_never_returns_
       derivative_only_phrase` pins that the canonical FTS never contains a
       derivative-only phrase.

### Step 4. Regression sanity (canonical hits unchanged)

4.1. Search for a word that visibly appears in a canonical on-screen answer
     (e.g. a distinctive noun from a mode-1 answer). Expect: ordinary
     canonical hits exactly as before this story - no "heard" group, no tag.
