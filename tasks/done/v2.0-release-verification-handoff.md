# Human-run verification handoff: story v2.0 MCP voice guide

Executable from its own text, per Testing protocol item 4 (`CLAUDE.md` /
`AGENTS.md`, "Testing protocol"). Run by a human; the agent prepared it and
stops. Everything below needs a live local model, speakers, a second process,
and a real Claude Code client, so none of it can be automated.

What this verifies: `--mcp-mode` serves one token-protected localhost MCP
server, an external assistant's answer reaches Jarvis and is spoken, the queue
and the interrupt hotkey behave, that answer is journaled and labeled as
somebody else's, and that it never becomes Jarvis's own model memory.

## Launch commands

Both start Jarvis in the voice-guide mode. Never run two at once (step 1).

```
Jarvis.cmd --mcp-mode
```

`Jarvis.cmd` is in the repository root (the Jarvis folder). Run it from a cmd
window in that folder. PowerShell does not run scripts from the current
folder by bare name, so there it is `.\Jarvis.cmd --mcp-mode`; every
`Jarvis.cmd` command below follows the same rule.

`Jarvis.cmd` runs `.venv\Scripts\python.exe -m jarvis --status-console %*` from
its own directory, so this start already opens the Status Console window -
that is what the mode badge and the voice-guide block below need. Without the
launcher:

```
python -m jarvis --mcp-mode --status-console
```

A manual `python -m jarvis --mcp-mode` (no `--status-console`) runs headless;
steps 1, 2, 4-7 and 9 need the console window.

Close Jarvis before switching modes: one instance at a time (step 1).

## Literal references used throughout

Every default is overridable by the named key in `config.toml`; check
`config.toml` and `config.ui.toml` first if a value below does not match your
install.

- `[mcp_mode].port` - **47821** (`McpModeSettings.port`,
  `src/jarvis/core/config.py:522`; documented at `config.example.toml:631`).
  The server always binds `127.0.0.1`; there is no host setting.
- `[mcp_mode].token_file` - **`mcp_mode.token`**
  (`McpModeSettings.token_file`, `src/jarvis/core/config.py:523`), a relative
  path against the working directory, so by default the file sits next to
  `Jarvis.cmd`. Created on the first `--mcp-mode` start; delete it to rotate
  the token. If your config sets a different name, that name is the one to
  read in step 3.1.

## Step 0. Prepare the settings state

0.0. Bring the launcher's environment up to `requirements.txt`. From the
     Jarvis folder run `.venv\Scripts\python.exe -m pip install -r
     requirements.txt`, then `.venv\Scripts\python.exe -m pip show mcp`.
     Expect `Version:` 1.30 or later (`requirements.txt`: `mcp>=1.30,<2`).
     `Jarvis.cmd` runs that `.venv` interpreter, and at the time of writing
     it held mcp 1.28.1, below the floor this story requires.

0.1. Open `config.toml` in the Jarvis folder. If the file does not exist,
     create it by copying `config.example.toml` and filling in the model and
     microphone sections, as README.md's setup section describes.

0.2. Find the `[mcp_mode]` section in `config.toml`. If the section is absent,
     add the header line `[mcp_mode]` and, under it,
     `canvas_speech = "derivative"`; that is all this handoff changes there,
     and it is exactly the default the rest of the handoff assumes. If the
     section exists, read its `port` and `token_file` and use your values
     instead of the defaults quoted above.

0.3. Make sure speech is on, otherwise every step below ends as "Not played:
     Jarvis is muted.":
     - in `config.toml`, `[tts] enabled = true`;
     - in `config.ui.toml` (the higher-precedence layer), `[tts] enabled` must
       be absent or `true` - if it says `false`, that is the effective value;
     - on the Status tab, the speech button must read "Mute" /
       "Заглушить". If it reads "Unmute" / "Включить звук", Jarvis is muted:
       click it once. The button stays usable in this mode
       (`run_mode.py:81`).

0.4. Make sure `[journal] enabled = true` in `config.toml`, so the calls
     recorded in steps 4-7 can be inspected.

0.5. Note which two files this handoff may have to change: `config.toml`
     (`[mcp_mode] canvas_speech`, step 0.2) and `config.ui.toml`
     (`[ui] language` in `config.ui.toml`, `UiSettings.language`,
     `src/jarvis/core/config.py:966`; documented at
     `config.example.toml:480-484`, step 9). Step 10 restores both.

0.6. Make sure no Jarvis is running (Task Manager, or press **Ctrl+Alt+Q** in
     a running one) before any start in this handoff.

## Step 1. Single instance

Every second start below (1.2-1.4) is refused with the same message; run it
from a **separate cmd window** so you can read its exit code, and expect a
modal message box you must dismiss with **OK** before the window continues:

1.1. Start `Jarvis.cmd --mcp-mode` and wait for the voice-guide block in the
     Status tab to read "Server: Listening" / "Сервер: Слушает".

1.2. Without closing it, in a second cmd window run `Jarvis.cmd`, then
     `echo %ERRORLEVEL%`. Expect a stderr line "Jarvis is already running.
     Only one instance may run at a time." and, because `Jarvis.cmd` passes
     `--status-console`, a message box with that text - click OK - printed at
     `src/jarvis/app.py:3413`, the box at `app.py:3414` for `--status-console`
     only. `echo %ERRORLEVEL%` must print **3**
     (`ALREADY_RUNNING_EXIT_CODE`; `Jarvis.cmd` ends with
     `exit /b %ERRORLEVEL%`).

1.3. Still with the first running, in that same second window run
     `Jarvis.cmd --mcp-mode`, then `echo %ERRORLEVEL%`. Expect the same
     refusal, the same OK box, and **3**: the two modes never run at once.

1.4. Shut the first one down (**Ctrl+Alt+Q**, `config.py:155`), start
     `Jarvis.cmd` (normal mode), and while it runs start `Jarvis.cmd
     --mcp-mode` in a second window. Expect the same refusal and **3** again -
     the guard is mode-independent.

1.5. Shut the normal one down and start `Jarvis.cmd --mcp-mode` again. Expect a
     successful start.

1.6. Kill the running Jarvis from Task Manager (End task) instead of closing
     it, then start `Jarvis.cmd --mcp-mode` again. Expect a successful start:
     the guard is a named mutex, so a dead process leaves no stale lock.

From here, every step's Jarvis session is titled "MCP session" /
"Сессия MCP", one per start. Keep track: step 4a is the first, steps 4b-4c the
second (a restart in 4b.1), steps 5-6 the third (the restart in 5.0); step 7
only reviews them.

2.1. With the console open, confirm the Status tab shows the run-mode badge
     "MCP MODE" / "РЕЖИМ MCP".

2.2. Confirm exactly what is disabled, and nothing more:
     - the thinking-mode level buttons ("Thinking mode" group) are greyed out,
       and **Ctrl+Alt+T** does nothing;
     - the response-mode group is greyed out, and **Ctrl+Alt+O** does nothing;
     - the Solo session checkbox is greyed out;
     - the MCP enable switch is greyed out;
     - every tool checkbox is greyed out;
     - the Journal "New context" button is greyed out;
     - the Journal input box, Send and Attach are greyed out;

2.3. Speak into the microphone for a few seconds. Expect nothing: no

2.4. Confirm the orb label reads "MCP waiting" / "MCP ожидает" and stays
     there while nothing is queued.

## Step 3. Client setup

3.1. Read the token in the Jarvis folder, cmd. With the default
     `[mcp_mode].token_file` that is:

     ```
     type mcp_mode.token
     ```

     If step 0.2 found a different `token_file`, run `type <that name>`
     instead. The output is the single line the file holds; that whole line is
     the bearer token (the loader strips surrounding whitespace, `token.py:49`).

3.2. If Claude Code already has a server named `jarvis`, drop it first:

     ```
     claude mcp remove jarvis
     ```

     (If `claude mcp list` does not show `jarvis`, skip this command.)

3.3. Register the server, with `-s user` so it is visible in every Claude Code
     session rather than only in sessions started in this folder, and with the
     port and token from step 0 / 3.1:

     ```
     claude mcp add -s user --transport http jarvis http://127.0.0.1:47821/mcp --header "Authorization: Bearer <the token from 3.1>"
     ```

     Replace `47821` with your `[mcp_mode].port` if it differs.

3.4. **Start a new Claude Code session** after registering: a session that was
     already running keeps the server list it started with.

3.5. In that new session run `/mcp`. Expect `jarvis` connected, exposing one
     tool, `speak`. Claude Code asks for permission on each `speak` call until
     you allow it permanently instead of once - answer the prompt as it comes,
     or pick the option that stops asking (its wording depends on the Claude
     Code version).

## Step 4. Origins

`speak` is the one MCP tool the `jarvis` server exposes (step 3.5). You never
call it yourself: you ask Claude Code in plain words, and Claude Code makes the
tool call. "Send X to `speak` with `canvas` / `spoken_text`" below means a
request such as "передай этот ответ в Jarvis через инструмент speak" and
names the tool arguments Claude Code should fill.

Session accounting: this step runs in two Jarvis sessions. 4a is in the first
MCP session; 4b.1 restarts Jarvis, so 4b and 4c are in the second.

4a. `canvas_speech = "derivative"` (set in step 0.2; Jarvis is running).

4a.1. In Claude Code ask for a long, dense technical answer, for example:
     "Объясни подробно, как устроен named mutex в Windows: CreateMutexW,
     GetLastError, ERROR_ALREADY_EXISTS, в чём разница с lock-файлом.
     Используй заголовки и ссылки на строки."

4a.2. Then ask Claude Code to hand that answer to Jarvis, for example:
     "передай этот ответ в Jarvis через инструмент speak, только canvas,
     без spoken_text". Approve the tool call if prompted.

4a.3. Expect the orb to read "Thinking" / "Думаю" with the substatus
     "Preparing an external answer..." / "Готовлю внешний ответ..." while the
     guide is written, then "Speaking" / "Отвечаю" with "Speaking an
     external answer..." / "Озвучиваю внешний ответ..." while it plays, then
     back to "MCP waiting" / "MCP ожидает". Expect a short spoken guide that
     names sections or files, not the whole canvas read aloud.

4b. `canvas_speech = "verbatim"`.

4b.1. Set `[mcp_mode] canvas_speech = "verbatim"` in `config.toml` and restart
     Jarvis (**Ctrl+Alt+Q**, then `Jarvis.cmd --mcp-mode`; the setting is read
     at startup). The port and the token did not change, so the running Claude
     Code session keeps working as is - do **not** start a new one, so the
     answer from 4a.1 stays in its context. Only if you had to re-register the
     server for any reason: start a new session and ask for a fresh long
     answer the same way as in 4a.1. Do not use `claude --continue` here - its
     help text promises the conversation, not the MCP servers.
     The restarted server no longer knows Claude Code's old MCP session and
     answers it with 404 "Session not found"
     (`.venv\Lib\site-packages\mcp\server\streamable_http_manager.py`, the
     unknown-session branch). Claude Code re-initializes on that, but the
     first `speak` call after the restart may still come back as an error. If
     it does, ask Claude Code to call `speak` again; if that fails too, run
     `/mcp` in Claude Code, select `jarvis`, choose Reconnect, and retry. The
     4a.1 answer stays in context throughout.

4b.2. Send the answer from 4a.1 to `speak` with only `canvas` (or the fresh
     one, if 4b.1 forced a new session). Expect the canvas itself to be read
     aloud - a long canvas takes minutes. The Journal row appears only after
     the speech has finished or been cut off, so wait for it instead of
     looking for it mid-speech. Its origin note reads "Spoken word for word."
     / "Озвучено дословно."

4c. Caller-supplied text, still in the `verbatim` session - `spoken_text`
     overrides the canvas regardless of `canvas_speech`.

4c.1. Ask Claude Code to call `speak` again with the same answer as
     `canvas` and a short, unmistakable `spoken_text`, for example: "вызови
     speak ещё раз: canvas - тот же ответ, spoken_text - 'Проверка: Jarvis
     говорит ровно этот текст.'" Expect exactly that text, nothing from the
     canvas.

4c.2. The Journal row shows the origin note "Spoken in the caller's
     wording." / "Озвучен текст вызывающей стороны."

## Step 5. Queue

5.0. Put `canvas_speech` back before queueing anything: set
     `[mcp_mode] canvas_speech = "derivative"` in `config.toml`, restart
     (**Ctrl+Alt+Q**, then `Jarvis.cmd --mcp-mode`) and start a new Claude Code
     session. Steps 5.1-5.2 and all of step 6 run in this third MCP session,
     in `derivative` mode.

5.1. In Claude Code, ask for a second long answer and pass it to `speak`
     twice in a row (two `speak` calls, no spoken_text). The second call
     returns a `queued` result with a position.

5.2. Expect both to be spoken one after the other, in order, with the second
     not cutting off the first. Watch the console queue row: it shows
     `<n> - speaking now` / `<n> - говорит сейчас` while one is playing and
     just `<n>` otherwise.

## Step 6. Interrupt

6.1. Repeat step 5.1: send the two `speak` calls again (the queue is always
     empty after 5.2).

6.2. Wait until speech starts, then press **Ctrl+Alt+I** (`config.py:170`)
     during the speech.

6.3. Expect: the current speech stops immediately, the queued item is never
     spoken, and both calls appear in the Journal - the one that was cut off
     with the note "Cut short by an interrupt." / "Прервано." and the one that
     was dropped with "Dropped before it was spoken." / "Выброшено из очереди
     до озвучивания." (both under the external-answer row; the statuses come
     from `strings.js:171-174,525-528`). The orb returns to "MCP waiting" /
     "MCP ожидает".

## Step 7. Journal

Three MCP sessions exist by now, all titled "MCP session" / "Сессия MCP": one
holding the single 4a call, one holding 4b and 4c, one holding steps 5 and 6.
A session is created per Jarvis start, lazily on the first recorded event
(`journal/recorder.py:255-259`), so the split is expected, not a defect. Do not
count on list order: find the sessions by their content, as below.

7.1. Open the Journal tab. Expect three sessions titled "MCP session" /
     "Сессия MCP" (an MCP-mode start that records nothing adds none).

7.2. Open the MCP session that holds exactly one call - the 4a one; the other
     two hold 4b+4c and the step 5-6 calls. Expect that call as a row whose
     source label reads "External answer - claude-code" / "Внешний ответ -
     claude-code" (the caller comes from the client's `clientInfo`), with the
     origin note "Spoken as a short guide." / "Озвучен краткий пересказ."

7.3. Search the Journal for an exact phrase from the canvas text (for
     example "ERROR_ALREADY_EXISTS"). The search covers every session, so the
     same phrase is expected to match the 4b and 4c calls too - several hits
     are the correct result, one per call that received this canvas.

7.4. Search for a phrase you heard only in the spoken guide (for example a
     fragment of the derivative from step 4a, which differs from the canvas
     wording). Expect it under the separate heard-phrase group, headed
     "Found by something you heard" / "Найдено по фразе, которую вы слышали",
     with the canvas shown as the authoritative text ("Shown on screen: " /
     "Было показано на экране: ").

7.5. Replay from the 4a row: "Play" plays that reply **and every later
     playable turn in the session back to back** (`audio/replay.py:485`,
     `app.js:2809-2812`) - it is not a single-row button. To hear only the
     guide from step 4a, click "Play" on the **last** row of that session, so
     the sequence is just that turn. While it runs the button reads "Stop" /
     "Стоп"; click it again to stop, or "Pause" / "Пауза" and "Resume" /
     "Продолжить" to hold the sequence.

7.6. Annotations, in the MCP session that holds the single 4a call. In that
     session open Annotations ("Annotations" / "Аннотации")
     and press "Generate for session" / "Сгенерировать для сессии". Expect a
     summary that treats the external answer as another assistant's text, and
     the annotation to be saved and editable. Annotate a session with several
     long canvases only if you raised `[history.annotation].max_source_chars`
     (default **24000**, `config.py:608`): several long canvases exceed it, and
     the run is then refused with `SOURCE_TEXT_TOO_LARGE`
     (`journal/annotation_generator.py:633-645`) instead of producing a
     summary.

## Step 8. Normal mode afterwards

8.1. Shut Jarvis down (**Ctrl+Alt+Q**) and start it normally:
