# Ручная проверка: история v2.0, голосовой гид MCP

Русский перевод `tasks/done/v2.0-release-verification-handoff.md`. При расхождении
верен английский файл.

Выполняется по собственному тексту, согласно пункту 4 Testing protocol
(`CLAUDE.md` / `AGENTS.md`, "Testing protocol"). Проверку проводит человек;
агент её подготовил и остановился. Всё ниже требует живой локальной модели,
динамиков, второго процесса и настоящего клиента Claude Code, поэтому
автоматизировать это нельзя.

Что проверяется: `--mcp-mode` поднимает один локальный MCP-сервер под токеном,
ответ внешнего ассистента доходит до Jarvis и озвучивается, очередь и хоткей
прерывания работают как задумано, этот ответ записывается в журнал и
помечается как чужой, и он никогда не становится собственной памятью модели
Jarvis.

## Команды запуска

Обе запускают Jarvis в режиме голосового гида. Никогда не запускайте две сразу
(шаг 1).

```
Jarvis.cmd --mcp-mode
```

`Jarvis.cmd` лежит в корне репозитория (папка Jarvis). Запускайте его из окна
cmd в этой папке. PowerShell не запускает скрипты из текущей папки по голому
имени, поэтому там нужно `.\Jarvis.cmd --mcp-mode`; это относится ко всем
командам `Jarvis.cmd` ниже.

`Jarvis.cmd` выполняет `.venv\Scripts\python.exe -m jarvis --status-console %*`
из своей папки, поэтому такой запуск сразу открывает окно Status Console - оно
нужно для значка режима и блока голосового гида ниже. Без лаунчера:

```
python -m jarvis --mcp-mode --status-console
```

Ручной `python -m jarvis --mcp-mode` (без `--status-console`) работает без
окна; шагам 1, 2, 4-7 и 9 окно консоли нужно.

Закрывайте Jarvis перед сменой режима: одновременно работает только один
экземпляр (шаг 1).

## Значения, на которые опирается проверка

Любое значение по умолчанию переопределяется указанным ключом в `config.toml`;
если значение ниже не совпадает с вашей установкой, сначала проверьте
`config.toml` и `config.ui.toml`.

- `[mcp_mode].port` - **47821** (`McpModeSettings.port`,
  `src/jarvis/core/config.py:522`; описан в `config.example.toml:631`).
  Сервер всегда слушает `127.0.0.1`; настройки хоста нет.
- `[mcp_mode].token_file` - **`mcp_mode.token`**
  (`McpModeSettings.token_file`, `src/jarvis/core/config.py:523`), путь
  относительно рабочей папки, поэтому по умолчанию файл лежит рядом с
  `Jarvis.cmd`. Создаётся при первом запуске `--mcp-mode`; удалите его, чтобы
  сменить токен. Если в вашем конфиге задано другое имя, в шаге 3.1 читайте
  именно его.
- `[mcp_mode].canvas_speech` - **`derivative`** или **`verbatim`**
  (`McpModeSettings.canvas_speech`, `src/jarvis/core/config.py:524`;
  допустимые значения в `config.py:512`). Читается один раз при старте, поэтому
  **после изменения нужен перезапуск Jarvis**.
- `[mcp_mode].queue_capacity` - **8** (`config.py:528`); вызов сверх неё
  отклоняется с `queue_full`.
- `[tts].enabled` - **`true`** (`TtsSettings.enabled`, `config.py:337`; секция
  по умолчанию в `config.example.toml`). Приоритет считается по каждому ключу
  отдельно, и `config.ui.toml` - верхний слой (`config.py:17-25`), так что
  значение в `config.ui.toml` побеждает тот же ключ в `config.toml`. В
  Settings его записывает флажок "Speak responses" / "Озвучивать ответы"
  (`strings.js:104,458`), а сохраняет кнопка "Apply" / "Применить"
  (`strings.js:138,492`) в `config.ui.toml` (`status_console.py:1037-1053`).
- `[journal].enabled` - **`true`** (`JournalSettings.enabled`, `config.py:550`;
  выключенный журнал ничего не записывает, `journal/recorder.py:167`).
- Хоткей прерывания: **Ctrl+Alt+I** (`HotkeySettings.interrupt`,
  `src/jarvis/core/config.py:170`). Единственный хоткей ввода, привязанный в

## Шаг 1. Один экземпляр

Каждый второй запуск ниже (1.2-1.4) отклоняется с одним и тем же сообщением;
выполняйте его из **отдельного окна cmd**, чтобы увидеть код выхода, и ждите
модальное окно сообщения, которое нужно закрыть кнопкой **OK**, прежде чем
окно cmd продолжит:

1.1. Запустите `Jarvis.cmd --mcp-mode` и дождитесь, пока блок голосового гида
     на вкладке Status покажет "Сервер: Слушает" / "Server: Listening".

1.2. Не закрывая его, во втором окне cmd выполните `Jarvis.cmd`, затем
     `echo %ERRORLEVEL%`. Ожидается строка в stderr "Jarvis is already running.
     Only one instance may run at a time." и, поскольку `Jarvis.cmd` передаёт
     `--status-console`, окно сообщения с тем же текстом - нажмите OK. Строка
     печатается в `src/jarvis/app.py:3413`, окно - в `app.py:3414`, только с
     `--status-console`. `echo %ERRORLEVEL%` должен вывести **3**
     (`ALREADY_RUNNING_EXIT_CODE`; `Jarvis.cmd` заканчивается
     `exit /b %ERRORLEVEL%`).

1.3. Пока первый всё ещё работает, в том же втором окне выполните
     `Jarvis.cmd --mcp-mode`, затем `echo %ERRORLEVEL%`. Ожидается тот же
     отказ, то же окно с OK и **3**: два режима никогда не работают вместе.

1.4. Выключите первый (**Ctrl+Alt+Q**, `config.py:155`), запустите `Jarvis.cmd`
     (обычный режим) и, пока он работает, запустите во втором окне
     `Jarvis.cmd --mcp-mode`. Ожидается тот же отказ и снова **3** - защита не
     зависит от режима.

1.5. Выключите обычный и снова запустите `Jarvis.cmd --mcp-mode`. Ожидается
     успешный запуск.

1.6. Вместо закрытия снимите работающий Jarvis в Диспетчере задач (Снять
     задачу), затем снова запустите `Jarvis.cmd --mcp-mode`. Ожидается
     успешный запуск: защита - это именованный мьютекс, поэтому мёртвый
     процесс не оставляет зависшей блокировки.

Дальше каждая сессия Jarvis называется "Сессия MCP" / "MCP session", по одной
на запуск. Следите за ними: шаг 4a - первая, шаги 4b-4c - вторая (перезапуск в
4b.1), шаги 5-6 - третья (перезапуск в 5.0); шаг 7 только просматривает их.

## Шаг 2. Форма режима

2.1. При открытой консоли убедитесь, что на вкладке Status есть значок режима
     "РЕЖИМ MCP" / "MCP MODE".

2.2. Убедитесь, что отключено ровно следующее, и ничего сверх:
     - кнопки уровня размышления (группа "Thinking mode") серые, и
       **Ctrl+Alt+T** ничего не делает;
     - группа режима ответа серая, и **Ctrl+Alt+O** ничего не делает;
     - флажок Solo-сессии серый;
     - переключатель MCP серый;
     - все флажки инструментов серые;
     - кнопка Journal "New context" серая;
     - поле ввода Journal, Send и Attach серые;
     - Fork / Continue у строки сессии серые;
     - **Ctrl+Alt+S** и **Ctrl+Alt+V** ничего не делают.
     Всё остальное остаётся доступным - в частности кнопка памяти, Play,
     аннотации, переключатель речи и кнопка "Apply" в Settings.

2.3. Говорите в микрофон несколько секунд. Ожидается ничего: ни индикатора
     записи, ни реплики, ни ответа.

2.4. Убедитесь, что подпись орба "MCP ожидает" / "MCP waiting" и не меняется,
     пока очередь пуста.

## Шаг 3. Настройка клиента

3.1. Прочитайте токен в папке Jarvis, в cmd. При `[mcp_mode].token_file` по
     умолчанию это:

     ```
     type mcp_mode.token
     ```

     Если в шаге 0.2 нашлось другое значение `token_file`, выполните
     `type <это имя>`. Вывод - единственная строка файла; вся она целиком и
     есть bearer-токен (загрузчик срезает пробелы по краям, `token.py:49`).

3.2. Если в Claude Code уже есть сервер с именем `jarvis`, сначала удалите его:

     ```
     claude mcp remove jarvis
     ```

     (Если `claude mcp list` не показывает `jarvis`, пропустите эту команду.)

3.3. Зарегистрируйте сервер с `-s user`, чтобы он был виден в любой сессии
     Claude Code, а не только в запущенных из этой папки, с портом и токеном из
     шага 0 / 3.1:

     ```
     claude mcp add -s user --transport http jarvis http://127.0.0.1:47821/mcp --header "Authorization: Bearer <токен из 3.1>"
     ```

     Если ваш `[mcp_mode].port` другой, замените `47821` на него.

3.4. После регистрации **запустите новую сессию Claude Code**: уже работавшая
     сессия сохраняет список серверов, с которым стартовала.

3.5. В новой сессии выполните `/mcp`. Ожидается, что `jarvis` подключён и
     предоставляет один инструмент, `speak`. Claude Code спрашивает разрешение
     на каждый вызов `speak`, пока вы не разрешите его насовсем, а не один раз
     - отвечайте на запрос по мере появления или выберите вариант, после
     которого он перестанет спрашивать (формулировка зависит от версии Claude
     Code).

## Шаг 4. Способы озвучки

`speak` - единственный MCP-инструмент сервера `jarvis` (шаг 3.5). Сами вы его
не вызываете: вы обычными словами просите Claude Code, и вызов инструмента
делает он. "Отправьте X в `speak` с `canvas` / `spoken_text`" ниже означает
просьбу вроде "передай этот ответ в Jarvis через инструмент speak" и называет
аргументы инструмента, которые Claude Code должен заполнить.

Учёт сессий: этот шаг идёт в двух сессиях Jarvis. 4a - в первой MCP-сессии;
4b.1 перезапускает Jarvis, поэтому 4b и 4c - во второй.

4a. `canvas_speech = "derivative"` (задан в шаге 0.2; Jarvis работает).

4a.1. Попросите Claude Code дать длинный плотный технический ответ, например:
     "Объясни подробно, как устроен named mutex в Windows: CreateMutexW,
     GetLastError, ERROR_ALREADY_EXISTS, в чём разница с lock-файлом.
     Используй заголовки и ссылки на строки."

4a.2. Затем попросите Claude Code передать этот ответ в Jarvis, например:
     "передай этот ответ в Jarvis через инструмент speak, только canvas,
     без spoken_text". Если появится запрос, разрешите вызов инструмента.

4a.3. Ожидается: пока пишется пересказ, орб показывает "Думаю" / "Thinking" с
     подстатусом "Готовлю внешний ответ..." / "Preparing an external
     answer...", пока он звучит - "Отвечаю" / "Speaking" с "Озвучиваю внешний
     ответ..." / "Speaking an external answer...", затем снова "MCP ожидает" /
     "MCP waiting". Ожидается короткий устный пересказ, называющий разделы или
     файлы, а не чтение всего canvas вслух.

4b. `canvas_speech = "verbatim"`.

4b.1. Задайте `[mcp_mode] canvas_speech = "verbatim"` в `config.toml` и
     перезапустите Jarvis (**Ctrl+Alt+Q**, затем `Jarvis.cmd --mcp-mode`;
     настройка читается при старте). Порт и токен не менялись, поэтому
     работающая сессия Claude Code продолжает работать как есть - **не**
     начинайте новую, чтобы ответ из 4a.1 остался в её контексте. Только если
     пришлось по какой-то причине перерегистрировать сервер: начните новую
     сессию и попросите новый длинный ответ так же, как в 4a.1. Не используйте
     здесь `claude --continue` - его справка обещает продолжение разговора, а
     не MCP-серверов.
     Перезапущенный сервер больше не знает старую MCP-сессию Claude Code и
     отвечает на неё 404 "Session not found"
     (`.venv\Lib\site-packages\mcp\server\streamable_http_manager.py`, ветка
     неизвестной сессии). Claude Code в этом случае переподключается сам, но
     первый вызов `speak` после перезапуска всё равно может вернуться с
     ошибкой. Если так, попросите Claude Code вызвать `speak` ещё раз; если и
     это не помогло, выполните в Claude Code `/mcp`, выберите `jarvis`, затем
     Reconnect, и повторите. Ответ из 4a.1 всё это время остаётся в контексте.

4b.2. Отправьте ответ из 4a.1 в `speak` только с `canvas` (или новый ответ,
     если 4b.1 потребовал новой сессии). Ожидается, что вслух читается сам
     canvas - длинный canvas занимает минуты. Строка в Journal появляется
     только после того, как речь закончилась или была прервана, поэтому
     дождитесь её, а не ищите посреди чтения. Её пометка о способе озвучки:
     "Озвучено дословно." / "Spoken word for word."

4c. Текст от вызывающей стороны, всё ещё в сессии `verbatim` - `spoken_text`
     имеет приоритет над canvas независимо от `canvas_speech`.

4c.1. Попросите Claude Code ещё раз вызвать `speak` с тем же ответом в
     `canvas` и коротким однозначным `spoken_text`, например: "вызови speak
     ещё раз: canvas - тот же ответ, spoken_text - 'Проверка: Jarvis говорит
     ровно этот текст.'" Ожидается ровно этот текст и ничего из canvas.

4c.2. У строки в Journal пометка о способе озвучки "Озвучен текст вызывающей
     стороны." / "Spoken in the caller's wording."

## Шаг 5. Очередь

5.0. Прежде чем что-то ставить в очередь, верните `canvas_speech`: задайте
     `[mcp_mode] canvas_speech = "derivative"` в `config.toml`, перезапустите
     (**Ctrl+Alt+Q**, затем `Jarvis.cmd --mcp-mode`) и начните новую сессию
     Claude Code. Шаги 5.1-5.2 и весь шаг 6 идут в этой третьей MCP-сессии, в
     режиме `derivative`.

5.1. Попросите Claude Code дать второй длинный ответ и передать его в `speak`
     два раза подряд (два вызова `speak`, без spoken_text). Второй вызов
     возвращает результат `queued` с позицией.

5.2. Ожидается, что оба прозвучат один за другим, по порядку, и второй не
     обрывает первый. Следите за строкой очереди в консоли: во время
     воспроизведения она показывает `<n> - говорит сейчас` /
     `<n> - speaking now`, в остальное время просто `<n>`.

## Шаг 6. Прерывание

6.1. Повторите шаг 5.1: снова отправьте два вызова `speak` (после 5.2 очередь
     всегда пуста).

6.2. Дождитесь начала речи и во время неё нажмите **Ctrl+Alt+I**
     (`config.py:170`).

6.3. Ожидается: текущая речь сразу обрывается, элемент из очереди так и не
     звучит, и оба вызова появляются в Journal - прерванный с пометкой
     "Прервано." / "Cut short by an interrupt.", выброшенный с пометкой
     "Выброшено из очереди до озвучивания." / "Dropped before it was spoken."
     (обе под строкой внешнего ответа; статусы из
     `strings.js:171-174,525-528`). Орб возвращается в "MCP ожидает" /
     "MCP waiting".

## Шаг 7. Journal

К этому моменту есть три MCP-сессии, все с названием "Сессия MCP" /
"MCP session": одна с единственным вызовом 4a, одна с 4b и 4c, одна с шагами 5
и 6. Сессия создаётся на каждый запуск Jarvis, лениво, при первом записанном
событии (`journal/recorder.py:255-259`), так что такое разделение ожидаемо и не
является дефектом. Не полагайтесь на порядок в списке: находите сессии по
содержимому, как ниже.

7.1. Откройте вкладку Journal. Ожидаются три сессии с названием
     "Сессия MCP" / "MCP session" (запуск в MCP-режиме, который ничего не
     записал, сессии не добавляет).

7.2. Откройте MCP-сессию, в которой ровно один вызов - вызов 4a; две другие
     содержат 4b+4c и вызовы шагов 5-6. Ожидается строка этого вызова с
     подписью источника "Внешний ответ - claude-code" / "External answer -
     claude-code" (вызывающий берётся из `clientInfo` клиента) и пометкой о
     способе озвучки "Озвучен краткий пересказ." / "Spoken as a short guide."

7.3. Найдите в Journal точную фразу из текста canvas (например
     "ERROR_ALREADY_EXISTS"). Поиск идёт по всем сессиям, поэтому та же фраза
     должна найтись и в вызовах 4b и 4c - несколько совпадений, по одному на
     каждый вызов с этим canvas, это правильный результат.

7.4. Найдите фразу, которую вы слышали только в устном пересказе (например
     фрагмент пересказа из шага 4a, отличающийся по формулировке от canvas).
     Ожидается, что она найдётся в отдельной группе поиска по услышанной фразе
     с заголовком "Найдено по фразе, которую вы слышали" / "Found by something
     you heard", а canvas показан как авторитетный текст ("Было показано на
     экране: " / "Shown on screen: ").

7.5. Повтор со строки 4a: "Воспроизвести" / "Play" проигрывает этот ответ
     **и все последующие воспроизводимые реплики сессии подряд**
     (`audio/replay.py:485`, `app.js:2809-2812`) - это не кнопка одной строки.
     Чтобы услышать только пересказ из шага 4a, нажмите "Воспроизвести" на
     **последней** строке этой сессии, тогда последовательность состоит из
     одной этой реплики. Во время воспроизведения кнопка показывает "Стоп" /
     "Stop"; нажмите её ещё раз, чтобы остановить, или "Пауза" / "Pause" и
     "Продолжить" / "Resume", чтобы приостановить последовательность.

7.6. Аннотации - в MCP-сессии с единственным вызовом 4a. В этой сессии
     откройте "Аннотации" / "Annotations" и нажмите "Сгенерировать для сессии"
     / "Generate for session". Ожидается резюме, в котором внешний ответ
     описан как текст другого ассистента, и аннотация сохраняется и
     редактируется. Аннотируйте сессию с несколькими длинными canvas, только
     если вы подняли `[history.annotation].max_source_chars` (по умолчанию
     **24000**, `config.py:608`): несколько длинных canvas его превышают, и
     запуск тогда отклоняется с `SOURCE_TEXT_TOO_LARGE`
     (`journal/annotation_generator.py:633-645`), а не даёт резюме.

## Шаг 8. Обычный режим после этого

8.1. Выключите Jarvis (**Ctrl+Alt+Q**) и запустите его обычно: `Jarvis.cmd`
     (или `python -m jarvis --status-console`).

8.2. Спросите о том, что было только во внешнем ответе (например
     "как работает ERROR_ALREADY_EXISTS?"). Ожидается обычный ответ, который
     не цитирует молча внешний canvas.

8.3. Попросите Jarvis поискать это в истории ("найди в истории, где
     обсуждался ERROR_ALREADY_EXISTS"). Ожидается, что результат подан как
     ответ другого ассистента, помечен как внешний с указанием вызывающего, а
     не как прошлый ответ самого Jarvis.

## Шаг 9. Визуальная проверка, в MCP-режиме

Блок голосового гида существует только в режиме запуска MCP
(`status_console_ui/app.js:328-331`), поэтому смотрите его там. Смена языка
интерфейса пишет `config.ui.toml` и вступает в силу после перезапуска
(`status_console.py:1037-1071`).

9.1. На вкладке Settings ("Настройки" / "Settings") выберите в "Язык
     интерфейса" / "Interface language" язык, которым вы сейчас не
     пользуетесь, и нажмите "Применить" / "Apply" (кнопка пишет
     `config.ui.toml`; консоль сообщит, что нужен перезапуск).

9.2. Выключите Jarvis (**Ctrl+Alt+Q**) и снова запустите его в режиме
     голосового гида: `Jarvis.cmd --mcp-mode`. Новой сессии в Journal не
     появится - сессия создаётся лениво при первом записанном событии
     (`journal/recorder.py:255-259`), а в этом шаге ничего не отправляется.

9.3. Просмотрите блок голосового гида на вкладке Status и строки Journal из
     шага 7 на этом языке, в привычном вам размере окна. Ожидается каждая
     строка из справочного раздела выше на соответствующем языке, без
     английского в русском интерфейсе и без обрезанного или наложенного
     текста.

9.4. Верните "Язык интерфейса" / "Interface language" на исходный язык,
     нажмите "Применить" / "Apply", затем **Ctrl+Alt+Q** и перезапустите.

## Шаг 10. Верните то, что изменили

10.1. В `config.toml` значение `[mcp_mode] canvas_speech` снова `"derivative"`
      (шаг 5.0), а заголовок `[mcp_mode]`, добавленный в шаге 0.2, всё ещё на
      месте - удалите секцию, если её раньше не было.
10.2. В `config.ui.toml` язык интерфейса возвращён к исходному (шаг 9.4).
      Кнопка "Apply" пишет полный снимок формы Settings, поэтому файл не
      совпадёт с прежним байт в байт - совпадут значения, а комментарии
      старого файла могут пропасть.
10.3. Запустите Jarvis так, как обычно (`Jarvis.cmd`), и убедитесь, что он
      поднимается как раньше.

## Отчёт

По каждому шагу: что ожидалось, что произошло, и точный текст консоли или
Journal там, где было расхождение. Шаг, который не удалось выполнить вовсе,
указывается как невыполненный с причиной - не пропускайте его молча.
