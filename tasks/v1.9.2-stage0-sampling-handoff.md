# Stage 0 sampling and execution handoff (human-run)

**Run:** v1.9.2 stage 0, run-id `v192-stage0-01`.
**Card:** `tasks/task-v1.9.2-9-stage0-damage-and-inertness-probe.md`.
**Stop rule record:** `tasks/v1.9.2-stage0-stop-rule.md`.
This handoff is self-sufficient: every command, config key, and default is
named literally. Run all commands from the repository root (`D:\AI\Jarvis`)
in PowerShell with `$env:PYTHONUTF8 = "1"` set for the session.

## Preconditions

1. Local Ollama is running at the endpoint from `config.toml`
   (`[backend] endpoint`, default `http://localhost:11434`); the configured
   model (`[backend] model`) is available locally. The harness validates the
   endpoint is loopback and refuses a `:cloud` model tag.
2. The Journal exists at the location from `config.toml` (`[journal] root`,
   default `journal` under the repo root).
3. The raw-output directory `manual_check_answer_revision_out/` is covered by
   the committed `.gitignore` rule (verified in commit
   `chore: ignore manual_check_answer_revision_out/ raw outputs before any
   payload`); nothing under it is ever committed.

## Step 1: sample (no model calls)

```powershell
$env:PYTHONUTF8 = "1"
python -m manual.manual_check_stage0_damage_probe sample
```

This lists the eligible-turn pool, selects the frozen sample (evenly spaced
by `floor((i+0.5)*N/30)` over the eligible turns recorded up to the end of
the protocol-freeze day, 2026-09-13, in the journal's local timezone; if
fewer than 30 exist, the whole pool and the shortfall are reported), and
writes to `manual_check_answer_revision_out/v192-stage0-01/`:
- `selection.json` - the pool size N, every selected and ineligible turn
  with reasons, and the out-of-window count (how many journal items the
  freeze window cut - 0 means nothing was cut, not that the window was
  unchecked);
- `scoring_sheet.csv` - one row per selected turn;
- `packets.jsonl` - the request text and published answer per turn.

Sampling happens once per run-id: a repeated `sample` refuses to run until
the run directory is deleted deliberately. Check `selection.json`: the
frozen target is 30; if the pool is smaller, stop and record N and
exclusions - the sample-size shortfall is a reported scope limit, not
something to backfill with ineligible turns.

## Step 2: pre-mark (owner, ~30 minutes)

Open `scoring_sheet.csv`. For each row:
1. Read the published answer and its request (`packets.jsonl` has full text;
   the sheet carries excerpts). The revision has not run yet - nothing
   exists to bias the mark.
2. Fill the `mode` column: `text`, `voice`, or `text_voice`. The column is
   pre-filled with `text_voice` when the Journal recorded a spoken
   derivative; empty means the schema cannot distinguish text from voice,
   so the owner decides. If you cannot mode-mark a turn with confidence,
   write `unknown` (or leave the cell empty) - that turn is recorded as
   mode-excluded and stays out of every denominator; it is never merged
   into `not_correct` and never blocks the run.
3. Fill the `pre_mark` column: `correct` or `not_correct`. Also confirm the
   two eligibility facts the Journal cannot record (bug report
   `2026-09-12-journal-turn-does-not-record-response-mode-or-reasoning-level.md`
   covers the mode; tool execution and retrieval/memory use are not
   journaled at all): if a turn used a tool or leaned on retrieved
   history/memory, mark it `not_correct` with that reason - it is excluded
   like any not-correct turn, and the reason keeps the exclusion auditable.

Only `correct` rows with `mode: text` enter the damage denominator;
`not_correct` rows and correct rows of a non-text or unknown mode are
recorded and excluded from revision, each with its own count. Rows with an
empty `pre_mark` are unfinished, not excluded - `run` stops and lists them.

## Step 3: dispatch revisions (one call per pre-marked-correct text turn)

```powershell
$env:PYTHONUTF8 = "1"
python -m manual.manual_check_stage0_damage_probe run
```

`run` never resamples: it reads the frozen selection from
`selection.json`/`packets.jsonl` and dispatches to exactly the turns the
owner pre-marked. Each dispatch is a production-shaped request - the same
effective system prompt a live turn gets (config `[prompts].system` plus
the curated memory files `memory/self.md` and `memory/memory.md`, composed
by the production `MemoryFileLoader.compose_system_prompt`) as the system
message, then the packet, the labeled draft, and the frozen instruction -
to the local `POST /api/chat` with the configured model, `think: false`,
seed `19200`, one turn at a time, append-only `ledger.jsonl`
(dispatched -> completed/failed/interrupted; no automatic retry). If any
selected turn has an empty `pre_mark` (not yet marked), nothing is
dispatched and the unfinished rows are printed. Raw responses land as
`revision-<turn_id>.json` files in the same run directory, where
`<turn_id>` is the turn id with its `#` replaced by `__` (for example,
turn `20260901-101500-ab#1` becomes
`revision-20260901-101500-ab__1.json`).

Interrupt safety: Ctrl+C stops future dispatches; the in-flight turn is
left as `interrupted` when the interrupt landed inside the model stream
and as `dispatched` when it landed between calls - either way it is an
unresolved record, and a re-run stops before dispatching when any planned
turn's latest ledger record is `dispatched` or `interrupted`, and lists
them. Resolve each one explicitly:

```powershell
python -m manual.manual_check_stage0_damage_probe resume completed <turn_id>
python -m manual.manual_check_stage0_damage_probe resume failed <turn_id>
python -m manual.manual_check_stage0_damage_probe resume reset <turn_id>
```

`completed`/`failed` record the outcome the owner verified from the
revision artifact; `reset` queues the turn for re-dispatch on the next
`run`. Only after every blocking turn is resolved does `run` proceed - it
never silently skips or retries an uncertain one.

## Step 4: score (owner, ~40 minutes)

For each pre-marked-correct text turn, compare the published answer with
`revision_text` from its artifact JSON. Fill the sheet's `label` column:
`unchanged` / `minor` / `improved` / `damaged` / `not_assessable`, plus a
short reason in the `reason` column. Definitions are frozen in the
stop-rule record; a not-assessable turn leaves the denominators and is
never counted as unchanged. Use the `fidelity_note` column for the
per-turn reconstruction-fidelity note: when a revision misread an
incomplete packet, the resulting damage is reported separately from
mechanism damage. One known reconstruction gap to watch for while scoring:
the probe does not carry the live turn's time context, so a draft that
said "сегодня" or "сейчас" is revised without the date it was written
under - damage on such a turn belongs in the fidelity note, not the
mechanism-damage count.

If the sheet is damaged (a spreadsheet mishap, a partial overwrite, a
deleted file), `python -m manual.manual_check_stage0_damage_probe template`
rebuilds the rows from the frozen selection and keeps every filled column;
with the sheet deleted entirely it rebuilds a blank sheet. It is not part
of the normal flow.

## Step 5: record the outcome

Tally the labels against the stop rule table and state the outcome with all
denominators (eligible pool N, selected, pre-marked correct/text, scored,
not-assessable, mode-excluded, not-correct, and the per-label counts).
Record it in the card and stop for the owner's decision - no stage-1 work
before that.
