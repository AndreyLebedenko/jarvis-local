# Stage 0 sampling and execution handoff (human-run)

**Run:** v1.9.2 stage 0, run-id `v192-stage0-01`.
**Card:** `tasks/task-v1.9.2-9-stage0-damage-and-inertness-probe.md`.
**Stop rule record:** `tasks/v1.9.2-stage0-stop-rule.md`.
This handoff is self-sufficient: every command, config key, and default is
named literally. Run all commands from the repository root (`D:\AI\Jarvis`)
in PowerShell with `$env:PYTHONUTF8 = "1"` set for the session.

## Preconditions

1. Local Ollama is running at the endpoint from `config.toml`
   (`[backend] endpoint`, default `http://localhost:11434`); the configured
   model (`[backend] model`) is available locally. The harness validates the
   endpoint is loopback and refuses a `:cloud` model tag.
2. The Journal exists at the location from `config.toml` (`[journal] root`,
   default `journal` under the repo root).
3. The raw-output directory `manual_check_answer_revision_out/` is covered by
   the committed `.gitignore` rule (verified in commit
   `chore: ignore manual_check_answer_revision_out/ raw outputs before any
   payload`); nothing under it is ever committed.

## Step 1: sample (no model calls)

```powershell
$env:PYTHONUTF8 = "1"
python -m manual.manual_check_stage0_damage_probe sample
```

This lists the eligible-turn pool, selects the frozen sample (the last 30
eligible completed turns; if fewer exist, the whole pool and the shortfall
are reported), and writes to
`manual_check_answer_revision_out/v192-stage0-01/`:
- `selection.json` - every selected and ineligible turn with reasons;
- `scoring_sheet.csv` - one row per selected turn;
- `packets.jsonl` - the request text and published answer per turn.

Check `selection.json`: the frozen target is 30; if the pool is smaller,
stop and record N and exclusions - the sample-size shortfall is a reported
scope limit, not something to backfill with ineligible turns.

## Step 2: pre-mark (owner, ~30 minutes)

Open `scoring_sheet.csv`. For each row:
1. Read the published answer and its request (`packets.jsonl` has full text;
   the sheet carries excerpts). The revision has not run yet - nothing
   exists to bias the mark.
2. Fill the `pre_mark` column: `correct` or `not_correct`.
3. Hand-mark the response mode of each turn (`text`, `voice`, or
   `text_voice`) in the `reason` column prefix or a personal note - the
   Journal schema does not record it (bug report
   `2026-09-12-journal-turn-does-not-record-response-mode-or-reasoning-level.md`).
   Turns you cannot mode-mark with confidence: exclude (leave `pre_mark`
   empty or mark `not_correct`) and note why.

Only `correct` rows enter the damage denominator; `not_correct` rows are
recorded and excluded from revision.

## Step 3: dispatch revisions (one call per pre-marked-correct turn)

```powershell
$env:PYTHONUTF8 = "1"
python -m manual.manual_check_stage0_damage_probe run
```

Each dispatch: local `POST /api/chat` with the configured model and current
effective settings, `think: false`, seed `19200`, one turn at a time,
append-only `ledger.jsonl` (dispatched -> completed/failed/interrupted; no
automatic retry; a re-run after an interruption prints unresolved records
and stops for your explicit decision on each). Raw responses land as
`revision-<turn_id>.json` in the same run directory.

Interrupt safety: Ctrl+C stops future dispatches; re-running `run` skips
turns with terminal statuses and never silently retries an uncertain one.

## Step 4: score (owner, ~40 minutes)

For each pre-marked-correct turn, compare the published answer with
`revision_text` from its artifact JSON. Fill the sheet's `label` column:
`unchanged` / `minor` / `improved` / `damaged`, plus a short reason in the
`reason` column. Definitions are frozen in the stop-rule record; a
not-assessable turn leaves the denominators and is never counted as
unchanged.

## Step 5: record the outcome

Tally the labels against the stop rule table and state the outcome with all
denominators (eligible, pre-marked correct, scored, not-assessable, and the
per-label counts). Record it in the card and stop for the owner's decision -
no stage-1 work before that.

## Boundaries

- Everything is local; no Journal content leaves the machine; no cloud calls.
- No runtime change; the Journal schema gap stays the filed bug report.
- Infrastructure errors stop per AGENTS.md - report and stop, no provider or
  shell changes.
