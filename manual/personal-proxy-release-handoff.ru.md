# Release handoff для ручной проверки: personal proxy, v2.1.0 (задача v2.1.0-12)

Русская копия `manual/personal-proxy-release-handoff.md`; при расхождении верен английский
оригинал. Выполняется по собственному тексту, по пункту 4 протокола тестирования
(`CLAUDE.md`). Запускает человек: нужны микрофон, колонки, GPU, живой локальный Ollama и
записанные корпуса спайков. Агент подготовил handoff и ничего из него не запускал. Он не
зависит от handoff-ов отдельных задач 5-10f: каждый ключ, команда и умолчание названы
ниже с источником. Пользовательская документация, на которую он опирается, - раздел
«Personal proxy mode» в `README.md` (английский) и «Режим персонального прокси» в
`README.ru.md` (русский), написанные в этой задаче.

На что отвечает, для `--personal-proxy`: (1) проходит ли голосовой или напечатанный запрос
весь конвейер в dry run и по-настоящему; (2) отправляет ли обмен подтверждения только по
чёткому «да» и не отправляет ничего при «нет», тишине или прерывании; (3) блокирует ли
детерминированный шлюз каждую категорию идентификаторов и файл тем; (4) восстанавливается
ли ответ в правильном русском падеже; (5) ничего ли не отправляет тишина; (6) помечают и
хранят ли Журнал и Status Console обмен, как задумано; (7) recall-отчёт: сколько
размеченных чувствительных данных всё ещё утекает, как часто система переспрашивает и как
часто зря отказывает.

Приватность: настоящий провайдер и настоящий ключ не нужны. «Внешняя» модель - это сам
Ollama на этом компьютере (шаг 1.3). Используйте только вымышленный текст; корпуса содержат
вымышленные личности. Ваш Журнал сохранит услышанные тексты этого прогона целиком (так
задумано); тестовые сессии можно потом удалить (вид Журнала, меню сессии «...»).

Автоматический аналог уже зелёный: `python -m pytest`, `ruff check`, `ruff format --check`.

## Точные ссылки

- Все команды выполняются из корня репозитория, в окружении, где обычно запускается
  `python -m jarvis`. Jarvis читает `config.toml` из текущей папки (`DEFAULT_CONFIG_PATH`,
  `src/jarvis/core/config.py`); отсутствующий ключ означает умолчание из кода
  (`config.example.toml` комментирует каждый ключ).
- Команда запуска (`parse_args`, `src/jarvis/app.py`):
  `python -m jarvis --status-console --personal-proxy`. `Jarvis.cmd` сам добавляет
  `--status-console`, так что `Jarvis.cmd --personal-proxy` - тот же запуск. Флагу нужен
  `--status-console`, и он несовместим с `--mcp-mode` и `--debug`.
- Используемые ключи `[personal_proxy]` (умолчания в `PersonalProxySettings`,
  `src/jarvis/core/config.py`): `endpoint` (умолчание `""`, обязателен), `model` (умолчание
  `""`, обязателен), `api_key_env` (умолчание `"JARVIS_PERSONAL_PROXY_KEY"`, ИМЯ переменной
  окружения с ключом), `dry_run` (умолчание `true`), `topics_file` (умолчание
  `"personal_proxy_topics.txt"`, относительно рабочей папки), `confirmation_timeout_seconds`
  (умолчание `20`), `doubt_min_listed` (умолчание `1`), `check_model` (умолчание
  `"gemma4:12b"`), `check_num_ctx` (умолчание `8192`), `stt_device` (умолчание `"cuda"`).
- Горячие клавиши (`HotkeySettings`, `src/jarvis/core/config.py`; переопределяются в
  `[hotkeys]` файла `config.toml`; если там что-то переопределено, берите показанные
  сочетания): завершение `Ctrl+Alt+Q`, прерывание `Ctrl+Alt+I`, сон микрофона
  `Ctrl+Alt+M`. В этом режиме привязаны только эти три.
- Текст окна - на языке `[ui].language` (умолчание `"en"`); handoff называет английские
  тексты (`src/jarvis/ui/status_console_ui/strings.js`), они приведены в кавычках как есть.
- Категории шлюза и их английские названия (`GateCategory`,
  `src/jarvis/personal_proxy/common/findings.py`; названия в
  `src/jarvis/personal_proxy/reporting/service_texts.py`): e-mail, phone, payment card, IBAN,
  long number, access key, password, street address, text from the topics file.
- Команда `/force` (`COMMAND_TABLE`, `src/jarvis/personal_proxy/request/request_commands.py`):
  напечатанный запрос, первый токен которого `/force` или `/f`, отправляется один раз без
  этапов локальной модели; детерминированный шлюз всё равно работает.
- Файлы отчётов пишутся в корень репозитория, в gitignored-папки `manual_check_*_out` и
  `personal_proxy_corpus*_wavs/`.

## 1. Разовая подготовка (не зависит от начального состояния)

1. Распознавание речи: `python -m pip install -r requirements-stt.txt`, затем один раз
   `python setup_stt_model.py` (нужна сеть). Ожидаемая последняя строка: «Done. The model is
   cached locally».
2. Ollama запущен на `[backend].endpoint` (умолчание `http://localhost:11434`), и
   `ollama list` показывает `gemma4:12b` (иначе `ollama pull gemma4:12b`).
3. Секция `[personal_proxy]` в `config.toml` должна содержать ровно эти ключи:

   ```
   [personal_proxy]
   endpoint = "http://localhost:11434/v1/chat/completions"
   model = "gemma4:12b"
   api_key_env = "JARVIS_PERSONAL_PROXY_KEY"
   dry_run = true
   topics_file = "personal_proxy_topics.txt"
   confirmation_timeout_seconds = 20
   doubt_min_listed = 1
   ```

   `endpoint` - собственный OpenAI-совместимый маршрут Ollama, заменитель внешней модели
   (`http` разрешён на `localhost`). Ничего не покидает компьютер.
4. В терминале, из которого запускается Jarvis (PowerShell): `$env:JARVIS_PERSONAL_PROXY_KEY =
   "handoff-test"`. Имя должно совпадать с `api_key_env`.
5. Создайте `personal_proxy_topics.txt` в корне репозитория (UTF-8, перезапишите) с одной
   строкой: `проект Лазурь`
6. Закройте запущенный Jarvis (`Ctrl+Alt+Q`) и другие программы, нагружающие GPU. Запомните,
   сколько сессий сейчас в виде Журнала: N0.

## 2. Запуск, ожидание и отказ в запуске

1. `python -m jarvis --status-console --personal-proxy`
2. Ожидается: открывается Status Console; орб показывает «Warming up the model...», затем
   «Waiting for a request»; один раз звучит сигнал «listening»; в верхней панели плашка
   «PERSONAL PROXY» и модель `gemma4:12b`; в панели событий «Personal proxy ready: the check
   model is warmed up»; на вкладке Status индикатор «DRY RUN - nothing is sent» и панель
   «Personal proxy».
3. Закройте (`Ctrl+Alt+Q`) и выполните
   `python -m jarvis --status-console --personal-proxy --debug`. Ожидается: окна нет; терминал
   печатает «--personal-proxy cannot be combined with --debug»; код выхода 2
   (`echo $LASTEXITCODE`). Затем снова запустите по 2.1.

## 3. Dry run (конфиг из шага 1.3: `dry_run = true`)

1. Скажите: «Позвони Марине Крыловой по номеру восемь девятьсот двенадцать триста сорок пять
   шестьдесят семь восемьдесят девять».
2. Ожидается ОДИН блок «Dry run - nothing was sent» с полями «Speech engine text», «Checked
   text», «Would ask», «Sanitized text» (плейсхолдеры вроде `<PERSON_1>`), «Mapping (stays on
   this machine)», «Verdict», «Outbound gate» и «Exact payload». Ничего не произносится, плашка
   локальности остаётся «Local». Сообщите, что показывает строка шлюза.
3. Напечатайте в доке вида Журнала «Расскажи коротко, что такое реле» и нажмите Send.
   Ожидается: dry-run блок, у которого «Speech engine text» пуст, а payload содержит вашу
   фразу.
4. Тишина: постучите по столу секунду. Ожидается: нет блока либо одно уведомление, что речь
   или текст не распознаны; ничего не отправляется; блока «Heard» нет.
5. Откройте вид Журнала. Ожидается: число сессий по-прежнему N0 (dry run ничего не пишет).

## 4. Настоящая отправка и восстановление (поставьте `dry_run = false`, перезапустите по 2.1)

1. Скажите: «Расскажи коротко, что такое реле». Ожидается по порядку: блок «Heard» с решением
   «Sending without a question», блок «Sent to the external model» (системный промпт свёрнут
   под подписью), затем предложения «Answer (external model)» появляются по одному и
   произносятся по одному. Пока ответ идёт, плашка локальности «External backend», в конце
   снова «Local».
2. Восстановление. Напечатайте в доке: «Напиши Марине Крыловой короткое письмо с
   благодарностью за вчерашнюю встречу». Ожидается: в блоке «Sent» вместо имени плейсхолдер
   (например `<PERSON_1>`), в ответе имя восстановлено в правильном падеже (например «Марине
   Крыловой»), ни одного плейсхолдера `<...>` не видно. Если в блоке написано «Plain
   substitution - the wording may be rough» или «Some placeholders could not be resolved»,
   сообщите; заменитель-модель может не сохранить плейсхолдеры, и это не дефект Jarvis.
   Повторите один раз с другим русским запросом, где названы человек, город и организация, и
   сообщите каждую восстановленную фразу.

## 5. Обмен подтверждения

1. Скажите запрос с адресом, продиктованным по буквам, например: «Напиши письмо на адрес
   i v a n p e t r o v собака g m a i l точка c o m». Сверка спрашивает примерно на 13 из 60
   размеченных записей, так что вопрос не гарантирован; пробуйте другие продиктованные
   адреса, пока он не появится (до десяти попыток). Когда он придёт, ожидается: блок «Heard»
   с решением «Asking you to confirm before sending», показывающий ВЕСЬ услышанный текст;
   голос называет, что проверить; пока он говорит, микрофон выключен, после - снова включён.
   - 5a. Ответьте голосом «да». Ожидается: отправлено, как в 4.1.
   - 5b. Повторите и ответьте «нет». Ожидается: ничего не отправлено; предложение исправить
     текстом или продиктовать заново произнесено и показано; блока «Sent» нет.
   - 5c. Повторите и молчите 20 секунд. Ожидается: как в 5b.
   - 5d. Повторите и напечатайте «да» в доке Журнала, затем Send. Ожидается: отправлено.
   - 5e. Повторите и ответьте неясно («может быть»). Ожидается: как в 5b.
   - 5f. Повторите и нажмите `Ctrl+Alt+I`, пока вопрос ждёт. Ожидается: как в 5b.
2. Прерывание во время ответа: начните 4.1 и нажмите `Ctrl+Alt+I`, пока ответ звучит.
   Ожидается: речь обрывается сразу, появляется уведомление, что запрос прерван, плашка
   возвращается в «Local», следующий ваш запрос слышен.
3. Сон микрофона: нажмите `Ctrl+Alt+M`; следующая реплика игнорируется; нажмите ещё раз;
   следующая реплика - запрос.

## 6. Блокировки шлюза и файл тем

Для каждой строки напечатайте сообщение в доке Журнала и нажмите Send. Префикс `/force`
пропускает этапы локальной модели, так что единственная защита - детерминированный шлюз, и
блок - ожидаемый результат. Каждый раз ожидается: уведомление «Blocked by the check, nothing
was sent:» с названием категории и позицией («message 1, characters A-B»), блока «Sent» нет,
а уведомление и строка Status «Last stop:» никогда не показывают само значение.

| Сообщение | Ожидаемая категория |
|---|---|
| `/force Привет, вот данные: anna.lebedeva@example.com спасибо` | e-mail address |
| `/force Привет, вот данные: +7 (915) 234-56-78 спасибо` | phone number |
| `/force Привет, вот данные: 4539 1488 0343 6467 спасибо` | payment card number |
| `/force Привет, вот данные: GB82 WEST 1234 5698 7654 32 спасибо` | IBAN |
| `/force Привет, вот данные: 4539 1488 0343 6468 спасибо` | long number |
| `/force Привет, вот данные: sk-proj-abcdEFGH1234ijklMNOP5678 спасибо` | access key |
| `/force Привет, вот данные: пароль: Zk9#mQ2x спасибо` | password |
| `/force Привет, вот данные: улица Ленина 5 спасибо` | street address |
| `/force Расскажи про проект Лазурь` | text from the topics file |

Затем без `/force` напечатайте: «Расскажи про проект Лазурь». Ожидается: запрос отклонён
(уведомление «The request was refused, nothing was sent.» с причиной) либо заблокирован
шлюзом; ничего не отправлено. Если он ушёл с темой, заменённой плейсхолдером, сообщите об
этом: тема не была отклонена.

Наконец, принудительный безобидный запрос: `/force Расскажи коротко, что такое реле`.
Ожидается: отправлен; блок «Sent» и Журнал показывают «FORCED: sent without the local
checks».

## 7. Метки Журнала и Status Console

1. Вид Журнала, новейшая сессия. Ожидается: её название «Personal proxy session» со временем
   начала; контурный значок «стрелка из коробки» и янтарная полоса слева у сессии и её
   сообщений; виды сообщений подписаны «Personal proxy - request», «Personal proxy - sent»,
   «Personal proxy - external answer», «Personal proxy - notice». У голосового запроса
   подпись «Spoken request; the recording is stored with it.».
2. Найдите в Журнале слово из голосового запроса, например «реле». Ожидается: результаты из
   proxy-сессии несут proxy-метки, а не «Jarvis».
3. Переименуйте сессию: меню «...» на ней, «Rename», введите `Release check`, Enter.
   Ожидается: список, шапка ленты и результаты поиска показывают это название. Очистите поле и
   сохраните: возвращается автоматическое название. Снова переименуйте в `Release check`.
4. «New context» (вид Журнала). Ожидается: новая proxy-сессия начнётся при следующем запросе;
   старая не изменилась. Скажите запрос.
5. Закройте Jarvis (`Ctrl+Alt+Q`) и запустите снова (2.1). Ожидается: обе сессии в списке,
   название `Release check` сохранилось.
6. Число сессий теперь N0 + 2 или больше, и ни в одной новой сессии нигде нет «Mapping» или
   ответа в виде плейсхолдеров.

## 8. Завершение и логи

1. В простое нажмите `Ctrl+Alt+Q`. Ожидается: окно закрывается, процесс завершается.
2. Запустите снова, начните ответ (4.1) и нажмите `Ctrl+Alt+Q`, пока он звучит. Ожидается:
   речь обрывается, процесс завершается, трейсбека нет.
3. Откройте новейший лог в `logs/` (`[logging]`, `LoggingSettings`). В нём не должно быть ни
   одной вашей фразы, услышанного текста, очищенного текста, текста ответа и названия сессии
   (только счётчики, виды и фиксированные сообщения). Сообщите о любой такой строке.

## 9. Recall-отчёт (размеченные корпуса)

Сначала закройте Jarvis. Эти инструменты читают записанные корпуса спайков: папки
`personal_proxy_corpus_wavs/` и `personal_proxy_corpus_v2_wavs/` (44 и 30 вымышленных реплик)
и сохранённые результаты `manual_check_confidence_out/`, `manual_check_confidence_v2_out/` и
`manual_check_text_sanitize_out/`. Если чего-то из этого нет, остановитесь и сообщите
владельцу: перезапись - это `manual/manual_record_personal_proxy_corpus.py`, она не входит в
этот handoff.

9.1 Доля утечек sanitize-прохода, офлайн (без модели и GPU):

    python -m manual.manual_check_text_sanitize score --v2-out manual_check_confidence_v2_out

Отчёт печатает таблицу решения и по каждой руке и группе validity, leak rate, mapping error
rate, preservation и false refusals сохранённых вызовов спайка v2.1.0-11 (использованный там
промпт держится равным production-промпту тестом
`tests/test_personal_proxy_sanitize_prompts.py`). Главная - первая таблица, рука G.
Записанный ориентир: validity 1.000, leak rate 0.052, mapping error rate 0.037, meaning
preservation 0.865, false refusal rate 0.235 (предел 0.15, принято владельцем).

9.2 Доля вопросов и покрытые ошибки, вживую (Whisper на GPU и живой Ollama): создайте
`config.handoff-b.toml` в корне репозитория (перезапишите; он в gitignore) со следующим
содержимым

```
[backend]
endpoint = "http://localhost:11434"
flash_attention = true
kv_cache_type = "q8_0"

[personal_proxy]
doubt_min_listed = 1
```

и выполните

    python -m manual.manual_check_doubt_trigger --config config.handoff-b.toml run

(`--config` идёт перед `run`). Проверяется 60 записей, это несколько минут; в конце - счётчики
и вердикт: `keep` (доля вопросов не больше 0.27, не меньше 6 из 7 настоящих ошибок
покрыты, не меньше 4 из 7 называют не тот фрагмент), `numbers_to_owner` или
`not_comparable`. Каким бы ни был вердикт, не меняйте `doubt_min_listed` и не запускайте
заново.

9.3 Ложные отказы на безобидных запросах (живой Ollama, 40 запросов, обе руки retry):

    python -m manual.manual_check_sanitize_false_refusals run --no-topics --out manual_check_sanitize_false_refusals_out/no-topics

Отчёт `manual_check_sanitize_false_refusals_out/no-topics/report.md` содержит по каждой руке
(`retry-on`, `retry-off`) `trials: 80`, счётчики по меткам (`send` - верно, любая другая
метка на безобидном запросе - ложный отказ или сломанный ответ), `retried:` и `rescued by the
retry:`. Записанный ориентир до появления retry: 23.5% ложных отказов.

## Что сообщить

По каждому шагу: что вы увидели против ожидаемого выше, своими словами, с точным текстом
любого уведомления или ошибки. Сначала сообщите всё, что было ОТПРАВЛЕНО, но не должно было
(блок «Sent» после «нет», тишины, тайм-аута, прерывания или блокировки шлюза), любое значение
из mapping или услышанный текст в строке лога, микрофон, оставшийся выключенным, и запущенный
proxy после неудачного запуска. Из части 9 сообщите такие числа: leak rate и validity
sanitize (9.1); долю вопросов, покрытые ошибки, число «не тот фрагмент» и вердикт (9.2);
долю ложных отказов и `rescued by the retry` для `retry-on` и `retry-off` (9.3). Владелец
записывает числа в `PROJECT.md` («Architecture v2.1.0», честные ограничения).
