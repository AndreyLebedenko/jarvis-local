# Ручной handoff: режимы речи персонального прокси, v2.1.1 (задача v2.1.1-6)

Выполняется по собственному тексту (пункт 4 протокола тестирования, `CLAUDE.md`). Запускает
человек: нужны колонки, микрофон (только для необязательного шага 2.4), GPU и живой локальный
Ollama. Агент подготовил handoff и ничего из него не запускал. От других handoff он не
зависит: каждый ключ, хоткей, команда и значение по умолчанию названы ниже с источником.
Пользовательская документация, на которую он опирается: подраздел «Режимы ответа в прокси» в
`README.ru.md` (русский) и `README.md` (английский).

На что отвечает, для `--personal-proxy`: (1) меняют ли хоткей и кнопки вкладки Status режим
ответа в режиме прокси; (2) отправляет ли Text по-прежнему обычный системный промпт и
озвучивает ли каждое предложение как пришло; (3) отправляет ли Voice абзац для озвучки и
озвучивает ли очищенные предложения, пока экран показывает ответ как пришёл; (4) озвучивает ли
Text+voice только после всего ответа, по локальной озвучиваемой версии, и возвращается ли к
запасному варианту, когда этот проход не удался; (5) пишет ли Журнал режим и озвученную
версию; (6) какая задержка у Text+voice на длинном ответе.

Приватность: настоящий провайдер и настоящий ключ не нужны. «Внешней» моделью служит сам
Ollama на этой машине (шаг 1.2). Используйте только выдуманный текст. Журнал сохранит
услышанные и напечатанные тексты этого прогона целиком (так задумано); после прогона сессии
можно удалить (вид Journal, меню сессии «...»).

Автоматический аналог уже зелёный: `python -m pytest`, `ruff check`, `ruff format --check`.

## Точные ссылки

- Все команды выполняются из корня репозитория. Jarvis читает `config.toml` из текущего
  каталога (`DEFAULT_CONFIG_PATH`, `src/jarvis/core/config.py`); отсутствующий ключ означает
  значение по умолчанию из кода (`config.example.toml` комментирует каждый ключ).
- Команда запуска (`parse_args`, `src/jarvis/app.py`):
  `python -m jarvis --status-console --personal-proxy`. Флагу нужен `--status-console`, он
  несовместим с `--mcp-mode` и `--debug`.
- Ключи `[personal_proxy]` (значения по умолчанию в `PersonalProxySettings`,
  `src/jarvis/core/config.py`): `endpoint` (по умолчанию `""`, обязателен), `model` (по
  умолчанию `""`, обязателен), `api_key_env` (по умолчанию `"JARVIS_PERSONAL_PROXY_KEY"`, ИМЯ
  переменной окружения с ключом), `dry_run` (по умолчанию `true`), `spoken_pass_timeout_seconds`
  (по умолчанию `30`, добавлен в v2.1.1), `check_model` (по умолчанию `"gemma4:12b"`),
  `check_num_ctx` (по умолчанию `8192`).
- `[response].mode` (`ResponseSettings.mode`, по умолчанию `"text"`) - режим при старте.
  Выпадающий список «Режим ответа» во вкладке Settings пишет `config.ui.toml` и может его
  переопределить, поэтому handoff не полагается на стартовый режим: шаг 2.2 задаёт режим
  кликом.
- Хоткей режима ответа (`HotkeySettings.response_mode_toggle`, `src/jarvis/core/config.py`,
  по умолчанию `Ctrl+Alt+O`; переопределяется в `[hotkeys]` файла `config.toml`; если секция
  его переопределяет, используйте показанную там комбинацию): каждое нажатие переключает
  Text -> Voice -> Text+voice -> Text. Остальные хоткеи в этом режиме: выход `Ctrl+Alt+Q`,
  прерывание `Ctrl+Alt+I`, сон микрофона `Ctrl+Alt+M`.
- На вкладке Status есть группа «Response mode» (в английском окне; текст окна следует
  `[ui].language`, по умолчанию `"en"`) с тремя кнопками «Text», «Voice» и «Text+voice»
  (`src/jarvis/ui/status_console_ui/strings.js`). Клик выбирает режим для текущей сессии.
- Печатать запрос можно в доке вида Journal; блок «Sent» сворачивает обычный системный промпт
  под подписью «Standard system prompt (click to show)».
- События Журнала лежат в `journal/<сессия>/events.jsonl` (`[journal].root`, по умолчанию
  `"journal"`, `src/jarvis/journal/store.py`). Событие ответа прокси имеет `source`
  `"proxy_answer"`; в его `metadata` есть `response_mode` и, для Text+voice при удавшемся
  локальном проходе, `spoken_derivative`.
- Абзац для озвучки (`VOICE_SYSTEM_PROMPT`, `src/jarvis/personal_proxy/common/payload.py`)
  начинается с обычного системного промпта и добавляет: "The answer will be read aloud: write
  plain prose without Markdown, lists, tables, headings or emphasis, and write abbreviations,
  units and symbols as full words."

## 1. Разовая подготовка (не зависит от состояния)

1. Ollama запущен по `[backend].endpoint` (по умолчанию `http://localhost:11434`), и
   `ollama list` показывает `gemma4:12b` (иначе `ollama pull gemma4:12b`). Распознавание речи
   (`requirements-stt.txt`, `setup_stt_model.py`) нужно только для необязательного шага 2.4.
2. Пусть секция `[personal_proxy]` в `config.toml` содержит ровно эти ключи:

   ```
   [personal_proxy]
   endpoint = "http://localhost:11434/v1/chat/completions"
   model = "gemma4:12b"
   api_key_env = "JARVIS_PERSONAL_PROXY_KEY"
   dry_run = false
   spoken_pass_timeout_seconds = 30
   ```

   `endpoint` - собственный OpenAI-совместимый маршрут Ollama, заменитель внешней модели.
   Ничего не покидает машину. `dry_run = false` нужен: сухой прогон ничего не отправляет.
3. В терминале, из которого запускается Jarvis (PowerShell):
   `$env:JARVIS_PERSONAL_PROXY_KEY = "handoff-test"`.
4. Закройте запущенный Jarvis (`Ctrl+Alt+Q`) и другие программы, активно использующие GPU.

## 2. Запуск и управление режимом

1. `python -m jarvis --status-console --personal-proxy`. Ожидается: открылась Status Console,
   виден значок «PERSONAL PROXY», сфера дошла до «Waiting for a request».
2. На вкладке Status кликните «Text» в группе «Response mode». Ожидается: «Text» выделена.
   Кликните «Voice», затем «Text+voice»: выделяется каждая по очереди, а в панели событий нет
   предупреждения об отказе (до v2.1.1 этот контрол здесь отклонялся).
3. Кликните «Text». Нажмите `Ctrl+Alt+O` один раз. Ожидается: выделена «Voice». Ещё раз:
   «Text+voice». Ещё раз: «Text». Сообщите о любом нажатии, которое ничего не меняет.
4. Необязательно (микрофон): в каждом режиме скажите короткую русскую фразу и убедитесь, что
   запрос начался. Пропустите, если вы только печатаете.

## 3. Режим Text

1. Кликните «Text». Напечатайте в доке Журнала и нажмите Send: «Перечисли по пунктам, сколько
   тысяч человек было в армии Наполеона в 1812 г. и какая была температура в ноябре, °C».
2. Ожидается: блок «Sent» (системный промпт свёрнут под «Standard system prompt (click to
   show)»; раскройте его: это ровно два предложения "Answer in the language of the request.
   Keep placeholders such as <PERSON_1> exactly as written."), затем предложения «Answer
   (external model)», озвучиваемые по одному как пришли (ответ с пометками списка или «**»
   читается вместе с ними; сокращения вроде «тыс.» читаются как написаны). Это прежнее
   поведение v2.1.0.

## 4. Режим Voice

1. Кликните «Voice». Напечатайте тот же запрос, что в 3.1.
2. Ожидается: раскрытый системный промпт блока «Sent» теперь содержит и абзац для озвучки,
   процитированный в «Точных ссылках». Экран показывает ответ как пришёл (в нём могут быть
   пометки списка или сокращения: это собственный вывод модели). В озвучке нет звуков
   Markdown, а «тыс.», «млн», «°C», «г.» после числа произносятся словами («тысяч», «градусов
   Цельсия», «года»). Речь начинается, пока ответ ещё идёт. Сообщите об одном предложении,
   показанном с маркером или сокращением, и как оно было озвучено.
3. Напечатайте: «Расскажи про XX век в двух предложениях». Ожидается: «XX век» звучит как
   «двадцатый век» (падеж берётся по следующему слову).

## 5. Режим Text+voice

1. Кликните «Text+voice». Напечатайте тот же запрос, что в 3.1. Запомните время T0 нажатия
   Send.
2. Ожидается: блок «Sent» показывает обычный системный промпт (без абзаца для озвучки);
   предложения ответа появляются на экране как пришли, и ничего не озвучивается; после
   последнего предложения идёт пауза (микрофон на паузе, идёт локальный проход), затем ответ
   озвучивается в форме, похожей на пересказ (он может ссылаться на экран). Запомните время
   T1, когда началась речь: задержка равна T1 - T0 минус время, за которое ответ стримился.
   Для длинного ответа (попросите около 400 слов) сообщите T1 - T0. Речь не должна
   начинаться раньше, чем последнее предложение окажется на экране.
3. Запасной вариант: в `config.toml` задайте `spoken_pass_timeout_seconds = 0.001`,
   перезапустите (2.1), кликните «Text+voice», снова отправьте запрос. Ожидается: пауза очень
   короткая, ответ озвучивается очищенным по предложениям, как в Voice. После этого верните
   значение `30` и перезапустите.
4. Прерывание: отправьте длинный запрос в «Text+voice» и нажмите `Ctrl+Alt+I`, пока длится
   пауза перед речью. Ожидается: ничего не озвучивается, микрофон возвращён.

## 6. Фиксация режима и Журнал

1. Кликните «Text+voice», отправьте длинный запрос и, пока ответ ещё идёт, кликните «Text».
   Ожидается: идущий запрос остаётся в Text+voice (локальный проход всё равно происходит);
   следующий запрос идёт в Text.
2. После запроса в каждом из трёх режимов выполните в PowerShell из корня репозитория:

   ```powershell
   Get-ChildItem journal -Recurse -Filter events.jsonl | Sort-Object LastWriteTime | Select-Object -Last 1 | ForEach-Object { Get-Content -Encoding UTF8 $_.FullName } | Select-String '"source":\s*"proxy_answer"'
   ```

   Ожидается: в каждой строке `proxy_answer` есть `response_mode` со значением `text`, `voice`
   или `text_voice`; `spoken_derivative` есть только в строке Text+voice с удавшимся
   локальным проходом. `text` события - ответ, каким он был показан.
3. В виде Journal откройте сессию Text+voice. Ожидается: у ответа есть свёрнутый блок
   «spoken aloud» с озвученной версией.
